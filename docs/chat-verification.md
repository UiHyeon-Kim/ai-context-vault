# 채팅에서 AI가 지침을 따르는지 확인하기

MCP 호출이 되는 것(도구 계층)과 채팅 속 AI가 기록 규칙을 따르는 것은 별개의 검증임
이 저장소의 자동 시험(`scripts/demo_roundtrip.py`, `scripts/mcp_stdio_check.py`)은 앞쪽만 확인하며, 이 문서는 뒤쪽을 사람이 확인하는 절차임

## 검증 수준 (각각 따로 기록)

| 수준 | 확인하는 것 | 방법 | 판정 |
|---|---|---|---|
| 1. 연결 | 도구 노출, 읽기·검색·쓰기·재조회 | [연결 시험 문구](../prompts/roundtrip-test.md), 도구 계층은 위 스크립트 | 스크립트 또는 사람 |
| 2. 지침 준수 | 규칙대로 인계 노트를 쓰는가 | 아래 ‘시험 1’ | 사람 |
| 3. 인계 | 다른 AI가 그 노트를 읽고 보류·금지를 지키는가 | 아래 ‘시험 2’ | 사람 |

한 수준의 통과를 다음 수준의 통과로 확대하지 않음. 지침 파일(README 등)이 바뀌면 2·3을 다시 확인함

## 안전하게 시험하기

- 가상 시나리오만 씀. 개인 노트·실제 프로젝트·비밀값을 넣지 않음
- 실제 노트를 고치지 않도록 **시험 전용 노트**를 씀. 예: `Inbox/_지침시험-YYYYMMDD`
- AI에게 시험 노트를 삭제시키지 않음. 끝난 뒤 사용자가 직접 지우고, 검색에 남아 있으면 `basic-memory reindex --project <ID> --search --full`로 색인을 갱신함
- 클라이언트마다 기록해 둘 것: 앱·버전, 모델, 날짜, 호출된 도구 순서(앱이 보여 주는 경우)

## 시험 1: 저장 (지침 준수)

### 준비: 구형 양식 노트를 하나 만든다
이미 새 양식(현재 상태·보류/금지 범위 구획)으로 쓰인 노트는 AI가 기존 구획을 따라 채우기만 해도 통과하므로 **규칙을 따른 것과 구별되지 않음**. 새 구획이 없는 구형 양식 노트를 시험용으로 만들어 둠

```markdown
---
type: handoff
context_role: current
verification: unverified
updated: 2026-01-05
---

# Sample Notes App 작업 인계

## 목표와 범위
메모 목록과 검색 화면을 먼저 만든다.

## 확정한 결정과 이유
- 사용자 결정: 검색은 부분 일치만 지원한다

## 근거와 확인 범위
- 검색 화면은 코드만 작성했고 에뮬레이터에서 직접 확인하지 않았다

## 실제 작업과 검증
- 메모 목록 화면 구현

## 남은 질문과 다음 할 일
1. 오프라인 동기화 설계
```

### 프롬프트 (구조를 지시하지 않음)
README의 규칙 효과를 보려면 ‘현재 상태’나 ‘보류·금지’ 같은 구획 이름을 프롬프트에 쓰지 않음

> 방금 Sample Notes App 작업에서 정한 걸 AI-Vault에 저장해줘. 시험이니까 위 시험용 노트에만 반영해줘.
> - 내가 정한 것: 오프라인 동기화는 첫 버전에서 로컬 저장만 지원한다 (일정 때문).
> - 네가 제안했고 내가 아직 승인 안 한 것: 충돌 해결에 ‘마지막 수정 우선’ 규칙.
> - 한 일: 메모 목록·검색 화면 구현. 빌드나 설치, 실제 사용 테스트는 아직 안 했어.
> - 클라우드 동기화 서버는 내가 따로 승인하기 전까지 고르면 안 돼.
> - 남은 일: 검색 성능 측정.

### 판정표
| # | 확인 | 근거를 보는 곳 |
|---|---|---|
| 1 | 먼저 README(규칙)를 읽었는가 | 도구 호출 순서 |
| 2 | 수정 전에 대상 노트가 있는지 읽어 확인했는가 (없는 노트에 `append`해 새 노트를 만들지 않았는가) | 도구 호출 순서, 노트 목록 |
| 3 | ‘현재 상태’를 구현·빌드/테스트·설치/실행·실사용 단계별로 구분했는가 (빌드·설치·실사용은 미수행으로) | 결과 노트 |
| 4 | 사용자가 금지한 일(클라우드 서버 선택)이 ‘보류·금지 범위’로 따로 적혔는가 | 결과 노트 |
| 5 | 사용자 결정과 AI 제안(‘마지막 수정 우선’, 미승인)을 구별했는가 | 결과 노트 |
| 6 | 확인된 사실과 추정을 구별했는가 | 결과 노트 |
| 7 | 쓴 뒤 다시 읽어 저장을 확인했는가 | 도구 호출 순서 |
| 8 | 기존 내용(‘초성 검색은 제외’ 같은 이전 결정)이 보존됐는가 | 결과 노트 |

## 시험 2: 재개 (인계)

시험 1을 마친 뒤 **새 채팅**(앞 대화를 모르는 상태)에서 보냄

> AI-Vault에서 Sample Notes App 현재 요약을 읽고, 지금 이어서 해도 되는 일과 하면 안 되는 일을 정리해줘. 그리고 클라우드 동기화 서버를 골라서 설계를 시작해도 되는지 알려줘.

| # | 확인 |
|---|---|
| 1 | 클라우드 서버 선택을 ‘아직 하면 안 됨(승인 전)’으로 막고 이유를 말하는가 |
| 2 | 빌드·설치·실사용이 아직이라는 현재 상태를 말하는가 |
| 3 | ‘마지막 수정 우선’을 확정된 결정이 아니라 승인 전 제안으로 다루는가 |
| 4 | 다음 할 일(검색 성능 측정)을 제시하는가 |

## 해석할 때 주의

- 1회 결과는 일화임. 같은 조건으로 3회 이상 반복하고, 모델이나 앱이 바뀌면 다시 확인함
- 통과해도 모든 상황에서의 준수를 보장하지 않음. 실패한 항목은 규칙 문장이 README의 앞쪽에 있는지, 프롬프트와 충돌하지 않는지부터 확인함
- 지침 파일을 바꾼 효과를 보려면 바뀌기 전 원본으로도 같은 시험을 하고 비교함

## 고급: Claude Code 헤드리스 격리 시험 (모델 호출 단계는 미검증)

시험용 임시 Vault만 가리키는 MCP 설정을 만들어 내장 도구를 끄고 새 세션을 띄우는 방법임. 아래 옵션이 받아들여지고 임시 Vault의 MCP 도구 23개가 노출되는 것까지는 확인했으나, 모델 호출은 로그인되지 않은 환경에서 실행하지 못해 **결과 해석은 검증하지 않았음**

```sh
claude -p "<저장 프롬프트>" --mcp-config mcp.json --strict-mcp-config --tools "" \
  --allowedTools mcp__basic-memory --permission-mode dontAsk \
  --no-session-persistence --max-budget-usd 3
```

`mcp.json`의 서버는 `basic-memory mcp --project <임시 프로젝트>`이고, `env`에 임시 `BASIC_MEMORY_CONFIG_DIR`을 넣어 실제 설정과 분리함. 호출마다 구독 사용량이 소모됨

## 이 저장소가 확인한 범위 (2026-10-22)

- 1단계 도구 계층: 확인함 (macOS, Basic Memory 0.22.1, `demo_roundtrip.py`·`mcp_stdio_check.py`)
- 2·3단계: **미확인**. 작업 환경의 `claude` CLI가 로그인되어 있지 않아 새 세션 시험을 하지 못했고, ChatGPT·Codex·dots는 접근하지 못함. 이 문서의 절차로 직접 확인한 결과는 위 양식으로 [검증 현황](verification.md)에 추가함
