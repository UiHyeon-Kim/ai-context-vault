## dots 실제 시험

1. 사용 중인 dot에 지정한 두 노트 읽기, 한글 검색, 인계 노트 끝에 검증 기록 추가와 최종 재조회를 요청함
2. dots가 `list_memory_projects`, `read_note`, `search_notes`, `edit_note`를 사용했다고 보고함
3. dots는 마지막 수정 후 재조회에서 고유 검증 표식이 정확히 한 번 존재한다고 보고함

README 첫 읽기는 HTTP 409 / MCP 서버 초기화 필요 오류가 발생했고 같은 요청을 순차 재시도해 성공했다고 dots가 보고함

이번에는 별도의 새 키·터널·권한을 추가하지 않고 기존 연결을 사용함

### 새로 확인한 동작 (Basic Memory 0.22.1)

- 새로 등록한 Vault는 `reindex` 전에는 MCP 검색이 비었음 (읽기·쓰기는 정상)
- 기본 검색은 의미 검색 구성요소가 있으면 hybrid. 임베딩 모델을 받지 못한 환경에서는 텍스트 색인이 있어도 **기본 검색이 0건**이었고, `text` 검색은 한글 접두어까지 정상이었음
- 온라인에서는 hybrid가 4개 질의 모두 관련 노트를 1순위로 반환했지만 5개 노트 전부를 반환함(표본이 작아 품질 평가는 아님). 기본 임베딩 모델 이름은 `bge-small-en-v1.5`
- `edit_note` 실패(`Edit Failed`)와 `read_note`의 노트 없음은 `isError: false`로 반환됨. 없는 노트에 `append`하면 오류 없이 새 노트가 만들어짐
- 확인 없이 `append`를 반복하면 내용이 중복됨. 사라진 문자열의 `find_replace`는 중단됨
- `project remove`는 `--delete-notes` 없이는 파일을 남기고, 기본 프로젝트는 지우지 못함
- 노트를 삭제하고 `reindex --search --full` 하면 검색에서 사라지고, 복구 후 `reindex`하면 다시 검색됨
- 첫 실행에서 임베딩 모델을 Hugging Face에서 내려받는 출력이 있었음
- 최신 버전 0.23.2(PyPI 최신, 같은 날 임시 가상환경에서 확인): 서버 동작(`Edit Failed` 응답이 `isError: false`, 없는 노트 `append`는 새 노트 생성, `text` 검색 필터)은 0.22.1과 같음. 다른 점은 둘: 임베딩 모델을 받지 못하면 `reindex --full`이 `Reindex failed: all vector embedding attempts failed.`와 함께 종료 코드 1로 끝나고(0.22.1은 0, 텍스트 색인은 둘 다 완성), 함께 설치되는 `mcp` SDK 2.x는 도구 결과 필드가 `is_error`임. 시험 스크립트는 두 가지를 모두 처리하도록 고쳤음
