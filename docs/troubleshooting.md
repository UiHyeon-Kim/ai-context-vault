# 도구 오류와 저장 여부 확인

이 저장소는 연결·운영 문서 모음이며 Basic Memory, 터널, 외부 서비스의 오류 처리를 직접 구현하지 않음
문서 보완이나 한 번의 호출 성공을 연결 장애 수정 완료로 보고하지 않음

## 먼저 구별할 상태

| 관찰 | 판단과 다음 행동 |
|---|---|
| 도구 자체가 제공되지 않음 | 해당 호출 미수행. 현재 채팅의 연결 여부를 확인 |
| `isError: true`와 `user cancelled MCP tool call` | 도구 오류로 기록. 문구만으로 사용자 취소나 특정 구현 버그를 확정하지 않음 |
| 시간 초과·연결 종료·쓰기 응답 손실 | 서버 반영 여부 미확인. 대상 노트를 읽기 전 같은 쓰기를 반복하지 않음 |
| 도구 성공 응답 | 쓰기는 대상의 최종 내용까지 재조회해 확인 |
| 로컬 파일 읽기 성공 | 파일 존재·내용만 확인한 결과. 원격 MCP·터널 성공과 구별 |

시간 초과·인증 실패·초기화 실패는 실제 반환된 오류에 근거해 구분함
취소 문구만 받은 호출에 원인을 추정해 붙이지 않음

## 읽기 요청이 실패했을 때

1. 발생 시각과 시간대, 사용 앱, 도구 이름, 읽기·쓰기 구분, 반환된 오류 문구를 남김
2. 응답에 요청 ID가 있으면 기록하고 없으면 미제공으로 적음. 관련 없는 ID를 대신 쓰지 않음
3. 사용자가 실제 취소·중단한 요청이면 멈춤. 직접 취소하지 않았고 일시 오류가 의심되는 읽기는 잠시 간격을 두고 같은 요청을 순차로 한 번 재시도함
4. 다시 실패하면 연속 호출을 멈추고 Mac 절전 여부와 터널·Basic Memory 프로세스의 실행 상태를 확인함

프로세스가 살아 있다는 사실만으로 요청을 정상 처리한다고 판단하지 않음
인증·권한 문제는 같은 호출을 반복해 해결하려 하지 않으며 임의로 키·토큰·상시 권한을 바꾸지 않음

## 쓰기 완료 여부가 불명확할 때

1. 같은 프로젝트와 정확한 노트 경로를 읽어 요청한 내용이 반영됐는지 확인함
2. 원하는 내용이 있으면 완료로 처리하고 같은 append·생성을 반복하지 않음. 시험용 고유 표식은 정확히 한 번인지 확인함
3. 재조회에 내용이 없더라도 원래 쓰기가 아직 서버에서 진행 중일 수 있음. 원래 호출의 서버 실행 종료와 미반영을 확인한 경우에만 최신 본문에서 필요한 부분을 다시 계산함. 종료 여부를 알 수 없으면 미확인으로 멈춤
   기존 내용을 정확히 지정한 `find_replace`와 `expected_replacements=1`처럼 범위가 좁은 편집을 우선함
4. 수정 직전에 다시 읽어 다른 AI의 변경을 보존하고, 수행한 편집을 마지막에 재조회함
5. 읽기도 실패하거나 변경이 충돌하면 저장 여부 미확인으로 남김. 다른 제목으로 새 노트를 만들거나 같은 본문을 다시 append하지 않음

고유 표식과 재조회는 중복을 발견하는 운영 절차이며 서버의 멱등성 보장은 아님
`expected_replacements`도 일치 개수 검사이지 파일 버전 잠금이나 여러 작성자 사이의 원자적 비교·저장을 보장하지 않음
현재 요약과 이력 중 한쪽만 반영됐다면 어느 쪽이 확인됐는지 구별해 알림

## 외부 서비스 확인이 필요할 때 남길 근거

발생·성공 시각과 시간대, 앱·설치 버전, 실패한 도구와 오류 문구, 요청 ID 제공 여부, 순차 재시도 결과, 로컬 상태와 원격 호출의 차이를 최소한으로 남김
노트 본문·전체 대화·자격증명·프로세스 환경 변수·실제 터널 식별자를 첨부하지 않음
이 정보만으로 원인을 좁힐 수 없다면 외부 클라이언트·터널·서비스 경계의 미확인 문제로 남김

[연결 시험](../prompts/roundtrip-test.md)과 [기존 검증 범위](verification.md)를 함께 확인함
