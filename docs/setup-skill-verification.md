# 초기 설정 스킬 검증

확인일: 2026-10-30. **macOS의 실제 Codex CLI에서 스킬 자동 발견 → 지침 등록 → 새 세션의 별칭 해석 → MCP 저장·재조회까지 확인했다.** 사용자 설정에 설치한 결과는 아니며, 독립된 임시 환경에서 관찰한 결과다.

## 최신 실제 클라이언트 시험

- 환경: Codex CLI 0.160.0, 모델 `gpt-6-astra`, Basic Memory 0.24.1, Python 3.12, macOS.
- 대상: 이 문서와 함께 수정한 `skills/vault-setup/SKILL.md`. SHA-256: `ae5926e0d3b2334be32f3bdd2ed513d9605a66f76757d9b5562778fe196d304e`.
- 임시 Git 프로젝트의 `.agents/skills/vault-setup/SKILL.md`에 스킬을 복사했다. 임시 홈·Codex 설정·Basic Memory 설정·DB·Vault를 사용하고 MCP는 `setup-live` 하나로 제한했다. 계정 앱·플러그인은 시험 설정에서 비활성화했다.
- 실제 설정 파일은 수정하지 않았다. CLI 인증에는 권한 600의 임시 인증 사본을 사용했으며 시험 후 삭제했다. 서버 자동 업데이트도 비활성화했다.
- 각 호출은 `--no-daemon --ephemeral`을 사용한 별도 세션이다. 저장 시험은 `--approve-for-me`로 승인 검토를 받으며 workspace-write 샌드박스를 유지했다. 승인 동작은 [공식 설정 참고](https://learn.chatgpt.com/docs/config-file/config-reference)의 `approvals_reviewer` 설명을 확인했다.

최종 변경에 대한 스킬 형식 검사, 기존 단위 테스트 52개, `git diff --check`도 통과했다. 이 검사는 위 실제 클라이언트 시험과 별개의 검증이다.

## 발견한 문제와 보완

1. **README를 읽지 못해도 지침을 등록함.** 기존 스킬은 프로젝트·도구 부재만 명시했다. README 본문 조회 실패도 등록 중단 조건으로 추가했다. 미색인 프로젝트에서는 등록하지 않는 것을 실제 CLI로 재확인했다.
2. **도구를 찾아보지 않고 연결이 없다고 판단함.** 첫 짧은 저장 요청은 별칭을 인식했지만 MCP 도구 탐색 없이 종료했다. 공통 지침에 클라이언트의 도구 검색을 먼저 사용하도록 추가했다. 수정된 스킬이 지침을 다시 생성한 뒤 새 세션에서 MCP 호출을 확인했다.

시험 환경 자체의 문제도 분리해 처리했다. 처음에는 계정 앱 커넥터가 노출되어 조회를 시도했지만 승인 정책에 막혔다. 이후 계정 앱을 끄고 임시 MCP만 사용했다. 미색인 README는 `reindex --search --project setup-live`로 텍스트 색인을 만든 뒤 정상 조회됐다. `write_note`로 기존 README를 색인하려던 시도는 기존 파일 충돌로 실패해 해당 경로는 사용하지 않았다. 의미 검색·임베딩은 검증하지 않았다.

초기 시험용 TOML을 조립할 때 모델·인증 저장소 키가 잘못된 테이블에 들어가 무시되는 경고도 발생했다. 두 키를 최상위로 옮긴 후 위 최종 시험을 진행했다. 최초 저장 호출은 시험용 `approval_policy=never`가 승인을 요구하는 MCP 쓰기를 거절했고, 재조회에서도 노트가 없었다. 이후 임시 실행을 자동 승인 검토 모드로 바꿔 저장·재조회가 성공했다. 실제 사용자 설정이나 전역 승인 정책을 변경한 결과가 아니다.

## 이전 행동 시험

`5b5572a`의 스킬을 별도 에이전트가 명시적으로 읽는 시험에서는 초기 등록, 기존 규칙 보존, 동일 설정 재적용 시 바이트 동일, 호칭·저장 방식 변경, Claude Code 대상 파일 선택, 도구 부재 시 초안 유지, 별도 문맥의 README 조회를 확인했다. 당시 실제 파일 317개의 해시가 같았다. Claude 대상 파일 작성도 Codex 에이전트로 수행한 것이며 실제 Claude 모델 시험은 아니다.
