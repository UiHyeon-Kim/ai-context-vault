# 현재 요약부터 읽는 노트 구조

노트 전체를 매번 읽는 부담을 줄이기 위해 현재 요약과 상세 이력을 분리함
기존 Basic Memory의 검색·메타데이터 필터를 사용하는 운영 방식이며 별도 자동 요약 엔진을 추가하지 않음

## 권장 구성

아래 이름은 구조를 설명하기 위한 예시이며 이 저장소에 개인 Vault 본문은 포함하지 않음

```text
AI-Vault/
  README.md                     # 짧은 일상 운영 규칙
  _views/
    Home.md                     # 주제별 링크만 모은 입구
    Vault-운영-상세.md           # 필요할 때 읽는 상세 규칙
  Inbox/
    관심-도구-수집.md            # 현재 요약
    이력/관심-도구-수집/
      2026-10-06-수집-기준.md    # 결정 이유와 당시 실행 근거
  Projects/
    Example.md                  # 프로젝트 정본 위치와 재개 요약
    이력/Example/
      2026-10-06-검증.md         # 당시 검증 범위
```

| 문서 | 남길 내용 | 읽는 시점 |
|---|---|---|
| 짧은 README | 필수 운영 규칙·탐색 순서 | 처음 접근·작업 재개 |
| 현재 요약 | 목표·범위·결정 이유·현재 확인 상태·미완료·다음 행동·출처 링크 | 해당 주제 재개 |
| 상세 이력 | 날짜별 실행·실패·원문 근거·과거 대안 | 근거가 필요한 경우 |
| 상세 운영 규칙 | 분류·이동·메타데이터 등 자세한 절차 | 해당 작업 수행 시 |

현재 요약은 대략 1~2천 자를 목표로 하되 중요한 실패·조건·반대 근거를 지우지 않음
짧은 일반 노트를 숫자에 맞춰 억지로 분리하지 않음
과거 기록에는 확인일과 한계를 유지하고 이번 편집일을 재검증일로 쓰지 않음

## 메타데이터와 검색

현재 요약에는 `context_role: current`, 상세 이력에는 `context_role: history`를 사용함
이 이름은 이 구성에서 정한 사용자 메타데이터이며 Basic Memory가 자동으로 분류해 주는 예약 기능이 아님
`context_role`은 읽는 역할, `verification`은 확인 수준이므로 현재 요약도 미검증일 수 있음

현재 요약을 우선 찾는 `search_notes` 인자 예시

```json
{
  "project": "ai-vault",
  "query": "관심 도구",
  "search_type": "text",
  "metadata_filters": {"context_role": "current"},
  "page_size": 3,
  "output_format": "json"
}
```

`search_type`을 `text`로 고정한 이유: 이 버전의 기본 검색은 의미 검색 구성요소가 있으면 hybrid인데, 임베딩 모델을 쓸 수 없는 환경에서는 텍스트 색인이 있어도 결과가 0건이었음. 텍스트 검색은 같은 조건에서 한글 접두어(`동기` → `동기화`)까지 찾았음
결과가 없거나 부족하면 필터를 제거하고 기존 일반 노트·제목·경로로 다시 찾음
경로가 확실하면 검색을 반복하지 않고 해당 요약을 바로 읽음
`page_size`는 결과 수이며 노트 본문 길이를 제한하는 설정이 아님
검증 환경의 `read_note`는 전체 본문을 반환했으므로 제목·노트를 먼저 좁혀야 함

## 갱신 순서

1. 수정 직전 현재 요약을 다시 읽어 다른 AI의 변경을 확인함
2. 새 실행 근거와 상세 기록을 날짜별 이력에 저장하고 재조회함
3. 현재 요약의 바뀐 결정·현재 상태·남은 일만 갱신하고 이력을 연결함
4. 마지막 수정 후 다시 읽어 확인함

요약과 이력은 두 파일이므로 한 번에 원자적으로 저장되는 것을 보장하지 않음
중간에 실패하면 어느 쪽까지 저장됐는지 알리고 다음 재개 때 불일치를 정리함
이전 이력 파일에 새 날짜의 로그를 계속 붙이지 않음

## 기존 긴 노트를 전환할 때

1. 변경 전 원문을 비공개 백업하고 크기·제목·참조 링크를 조사함
2. 현재 재개에 꼭 필요한 결정·이유·실패·미완료·정본 위치를 추출함
3. 원문을 주제·제목 경계로 상세 이력에 먼저 보존함
4. 기존 경로에 현재 요약을 두어 기존 링크가 계속 현재 입구를 가리키게 함
5. 제목 앵커·상대 경로 링크가 있으면 새 위치에 맞게 대조함
6. 원문 보존, 새 링크, 다른 노트의 변경 여부와 MCP 검색·재조회를 확인함

[현재 요약 양식](../templates/handoff.md), [상세 이력 양식](../templates/history.md), [짧은 README 양식](../templates/vault-readme.md)을 참고함
양식을 다른 Vault로 복사한 뒤에는 예시 설명과 저장소 상대 링크를 제거하거나 실제 노트 경로로 바꿈

## 효과와 한계

저장량 자체가 아니라 AI에게 전달되는 본문을 줄이는 방식임
원문을 보존하므로 전체 저장량은 늘 수 있으며 모든 이력을 다시 읽으면 절약되지 않음
요약 누락·오래된 요약·필터로 숨겨진 기존 노트는 근거 링크와 필터 없는 재검색으로 보완함
문자 수 감소가 실제 모델의 토큰·요금 감소율과 같지는 않으며 도구 결과·메타데이터도 별도 분량임
규칙과 양식을 추가해도 AI가 항상 자동으로 준수한다고 보장하지 않음
