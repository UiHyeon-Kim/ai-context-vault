# Vault 운영 규칙 양식

Vault의 README에 맞춰 적용할 짧은 규칙 예시
기존 폴더 책임과 규칙을 보존하고 아래 읽기·기록 방식을 병합함

## 읽는 순서

1. 처음 접근하거나 작업을 재개할 때 README를 읽음
2. 경로를 알면 해당 주제의 현재 요약을 바로 읽음
3. 모르면 제목 검색 또는 탐색 뷰에서 찾고 현재 요약부터 읽음
4. 현재 요약 우선 검색은 metadata_filters={"context_role":"current"}, page_size=3으로 시작함
5. 없거나 부족하면 필터를 풀고 일반 노트·다른 제목·경로를 확인함
6. 상세 이력과 원출처는 판단 근거가 필요할 때만 읽음

같은 작업에서 이미 읽은 운영 규칙을 매번 다시 읽거나 연결 설정 노트를 모든 작업의 필수 입구로 삼지 않음

## 갱신과 보존

- 현재 요약에는 목표·결정과 이유·확인한 상태·미완료·다음 행동·출처를 유지함
- 날짜별 실행 로그는 같은 분류의 이력/주제/에 나누고 요약에서 연결함
- 현재 요약은 context_role: current, 이력은 context_role: history로 표시함
- 수정 직전 기존 본문을 읽어 다른 AI의 변경을 보존하고 마지막 수정 후 재조회함
- 정리할 때 기존 원문을 보존하고, 편집일과 실제 검증일을 구별함
- 코드·ADR·백로그는 repo, 외부 학습 본문은 원출처가 정본임
- 사용자 발언·AI 제안·실행 결과·미확인을 구별함
- 전체 대화·비밀정보·불필요한 개인정보는 저장하지 않으며 저장 금지 요청을 우선함
- 도구가 없으면 미수행, 오류·응답 손실로 저장 여부를 모르면 미확인으로 보고함. 대상 재조회 전에 쓰기를 재전송하거나 다른 서비스에 임의로 대체 저장하지 않음

## 상세 규칙과 탐색

기존 상세 규칙을 별도 문서로 분리했다면 실제 경로를 여기에 연결함
주제별 탐색 뷰에는 링크만 두고 현재 상태 본문을 중복 관리하지 않음
기록 시점·출처·검증 단계 기준은 [공용 지침](../prompts/shared-context.md)을 참고해 실제 Vault의 운영 규칙 정본에 한 번만 반영함
