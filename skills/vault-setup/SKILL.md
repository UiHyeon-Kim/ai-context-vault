# Vault 기록 규칙 초기 설정

## 선택과 연결 확인

사용할 AI, 현재 프로젝트 또는 개인 전체 적용 범위, 실제 Basic Memory 프로젝트, 저장 방식(요청 시 / 중요한 결정도 기록)을 확인한다. 이미 정한 선택은 다시 묻지 않는다. 저장 방식만 미지정이면 요청 시 저장을 기본으로 한다. 대상 AI·범위·프로젝트가 모호하면 쓰기 전에 필요한 항목만 묻는다.

AI에게 부를 호칭도 선택하게 한다(예: Vault, 내 메모장, 작업노트). 기존 설정이 있으면 그 호칭을 유지하고 새 설정에서 미지정이면 Vault를 기본값으로 제시한다. 호칭은 프로젝트 ID·폴더·앱 커넥터 표시 이름과 별개의 자연어 별칭이다. 이름 변경 요청이 어느 종류인지 불명확하면 먼저 구분한다. 이 스킬은 호칭과 그 지침만 변경하며 프로젝트 재등록·폴더 이동·앱 표시 이름 변경은 수행하지 않는다.

현재 제공된 도구로 프로젝트와 README를 읽어 연결을 확인한다. 프로젝트가 없거나 도구를 사용할 수 없으면 연결 미완료로 알리고 지침 초안까지만 준비한다. 지침을 추가하는 것만으로 MCP 연결이 생긴다고 설명하지 않는다. 패키지·터널·인증 설치는 별도 요청 범위이며 임의로 수행하지 않는다.

## 선택한 범위에 지침 등록

실제 클라이언트의 지침 위치와 기존 내용을 먼저 확인한다. Codex는 선택한 프로젝트/개인 범위의 AGENTS.md, Claude Code는 CLAUDE.md, 그 밖의 앱은 지원하는 사용자/프로젝트 지침을 사용한다. 경로나 적용 방식이 다르면 해당 환경의 공식 문서를 확인한다. 웹 앱의 지침을 수정할 수 없으면 붙여넣기용 블록을 제공하고 사용자 적용 대기로 표시한다.

아래 블록의 프로젝트 값을 실제 선택으로 바꾼다. 블록은 지침 파일 내부의 텍스트이며 저장소 상대 파일 경로에 의존하지 않는다. 수정 요청을 받은 파일만 편집하고 기존 내용을 보존한다. 재실행 시 기존 AI-Vault 블록을 갱신하며 중복 추가하지 않는다. 다른 위치의 Vault 규칙과 충돌하면 조용히 덮어쓰지 말고 적용 범위를 확인한다.

블록의 호칭을 사용자 선택으로 치환하고 실제 프로젝트와의 대응을 명시한다. 호칭은 단일 줄의 일반 이름으로 받고 지침·Markdown 블록을 이름으로 삽입하지 않는다. 기존 호칭 변경 시 해당 블록의 요청 예시도 함께 갱신한다. 다른 프로젝트와 같은 호칭이 겹치면 임의로 연결하지 말고 구별할 이름을 확인한다. 관리용 제목 `AI-Vault`는 중복 식별을 위해 유지한다.

```text
## AI-Vault

- 사용자가 부르는 호칭 `<선택한 호칭>`은 Basic Memory의 `<선택한 프로젝트>`를 뜻한다.
- “<선택한 호칭>에 기록해줘”는 현재 주제의 핵심 내용 저장, “<선택한 호칭>에서 이어서 하자”는 관련 최신 노트 조회, “<선택한 호칭>에 인계해줘”는 다음 작업을 위한 요약 갱신으로 해석한다.
- 저장은 사용자가 요청할 때 수행한다. 조회 요청만으로 쓰지 않는다.
- Vault 접근 시 README 운영 규칙을 확인하고 현재 요약부터 읽는다. 상세 이력은 필요한 근거만 읽는다.
- 저장 전 관련 기존 노트를 찾아 다시 읽는다. 현재 대화로 주제가 명확하면 이어서 갱신하고, 대상이 여러 개라 모호하면 먼저 확인한다. 기존 노트가 없으면 README의 분류 규칙에 따라 새 노트를 만든다.
- 기본은 요약·근거·다음 할 일이다. 결정과 이유·보류·금지·실행/검증 상태는 해당 내용이 있을 때 추가한다. 실제 조건과 실패를 생략하거나 빈 양식을 채우려고 사실을 만들지 않는다.
- 사용자 결정·AI 제안·확인한 사실을 구분하고 긴 실행 이력은 분리한다. 저장 후 다시 읽어 확인하고 저장 경로를 알린다.
- 도구가 없으면 미수행, 응답이 끊기면 미확인으로 보고한다. 쓰기 재시도 전에 실제 저장 여부를 확인한다. 전체 대화·비밀정보는 일괄 저장하지 않으며 저장 금지 요청을 우선한다.
```

사용자가 ‘중요한 결정도 기록’을 선택한 경우에만 세 번째 항목을 다음으로 교체한다. 두 방식을 동시에 남기지 않는다.

> 저장 요청뿐 아니라 중요한 사용자 결정·조사 결론·작업 인계가 생기면 관련 노트에 반영한다. 단순 잡담·중간 진행은 누적하지 않으며 사용자의 저장 보류·금지를 우선한다.

Vault README 자체에 자동 기록 의무 등 선택과 충돌하는 규칙이 있다면 초기 설정만으로 해결했다고 보고하지 않는다. 해당 Vault 규칙까지 수정할지는 사용자에게 확인한다.

## 완료 확인

편집한 지침을 다시 읽어 호칭과 대상 프로젝트의 대응·저장 방식·기존 내용 보존·중복 여부를 확인한다. 호칭만 바꾼 경우 기존 프로젝트 ID와 연결 설정이 그대로인지 확인한다. 설정 파일 저장과 새 채팅에서 지침 로드는 구분한다. 새 채팅에서 설정된 호칭·프로젝트 조회 → 사용자 요청에 따른 작은 기록 → 재조회를 권한다. 시험 기록을 만들 권한이 없으면 임의로 쓰지 않는다.

등록한 파일 또는 붙여넣을 위치, 선택값, 연결 확인 범위와 미검증 단계를 보고한다. 이 스킬은 초기 설정 절차이며 백그라운드 저장 서비스나 모든 AI에서 통용되는 슬래시 명령이 아니다.
